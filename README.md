# Customer Enquiry Webhook Automation

A self-hosted n8n workflow that receives customer enquiries through an HTTP POST webhook, routes them by message keywords, and returns a structured JSON response.

## Workflow

1. **Webhook** receives a POST request containing `customer_name`, `email`, and `message`.
2. **Edit Fields** extracts those values from the request body.
3. **Switch** routes the message:
   - Contains `payment` → Payment Support
   - Contains `order` → Order Support
   - Otherwise → General Support (fallback)
4. The selected branch sets `department`, `handling_status`, and `response`.
5. **Respond to Webhook** returns the processed JSON item.

## Example request

```json
{
  "customer_name": "Priya",
  "email": "priya@example.com",
  "message": "I need help with my payment"
}
```

## Test with PowerShell

Replace the URL with the Production URL generated by your own n8n instance.

```powershell
$body = @{
    customer_name = "Priya"
    email         = "priya@example.com"
    message       = "I need help with my payment"
}

$response = Invoke-RestMethod `
    -Method POST `
    -Uri "YOUR_N8N_PRODUCTION_WEBHOOK_URL" `
    -ContentType "application/json" `
    -Body ($body | ConvertTo-Json)

$response | ConvertTo-Json -Depth 5
```

## Routing outcomes

| Message contains | Department | Handling status |
|---|---|---|
| `payment` | Payment Support | `urgent` |
| `order` | Order Support | `normal` |
| Neither keyword | General Support | `pending` |

**Matching is case-sensitive** in this workflow. It uses simple keyword matching, not semantic classification.

## Import into n8n

1. Open your n8n instance.
2. Create a workflow and choose **Import from File** (menu wording may vary).
3. Select `workflow/customer-enquiry-webhook.json`.
4. Open the Webhook node and use the Production URL generated by your own instance.
5. Save and publish the workflow.
6. Test using the PowerShell example above.

The public template uses the placeholder webhook path `customer-enquiry` and is inactive by default. Your n8n instance will generate its own endpoint.

## Security and scope

- This repository is a portable workflow template, not a hosted service.
- The Webhook node has no authentication configured. Do not expose it publicly for real customer data without adding authentication, input validation, rate limiting, and appropriate operational safeguards.
- The workflow returns routing information and a response message. It does not send emails, create support tickets, or contact a department.
- Sample names and email addresses are illustrative.
